# feedzine

RSS/Atom фиды → периодические «журналы» в EPUB. Заточено под e-ink читалки:
true-grayscale картинки, вписывание в бокс экрана, baseline JPEG, книжная
типографика. Python + typer/rich/textual/httpx/pydantic/Pillow, pandoc
для сборки — всё из Nix flake.

Каждый `feedzine issue` собирает **выпуск** из статей, появившихся в фидах
с прошлого выпуска: сводка из фида или полный текст (Habr — через kek/v2,
остальные сайты — `<article>`-extractor), статьи группируются по фидам,
в навигацию попадают и фиды, и статьи. Прочитанное помечается в state —
дубликатов между выпусками нет.

## Установка

```bash
nix run github:71g3pf4c3/feedzine -- init   # напишет ~/.config/feedzine/config.toml
nix profile install github:71g3pf4c3/feedzine
```

## Использование

```bash
feedzine init                          # пример конфига
feedzine list                          # фиды, сколько нового (rich-таблица)
feedzine list --json                  # то же, машиночитаемо
feedzine issue                         # собрать выпуск из нового
feedzine issue --preset mini --text-only
feedzine issue --format html           # epub (default) | html | md
feedzine issue --dry-run              # что попадёт в выпуск, state не трогает
feedzine tui                           # интерактивно: отметить фиды, собрать
feedzine web                           # webui в браузере (127.0.0.1:8097)
```

`tui`: таблица фидов с живым счётчиком новых, `space` — вкл/выкл фид,
`f` — полный текст/сводки, `+`/`−` — кап фида, `i` — выпуск (периоды
журналов уважаются: недельная сводка не соберётся раньше границы),
`I` — форс-сводка из копилки, `d` — dry-run, `r` — обновить. Статус-бар
показывает по каждому журналу номер выпуска, копилку и период; вывод
сборки — в лог-панель под таблицей.

`web`: то же из браузера — карточки журналов (номер, копилка, период),
таблица фидов с кнопкой «проверить» (живой опрос фидов), «собрать выпуск»
(с чекбоксом форса) и хвост лога сборки. Конфиг web не правит — только
смотрит и собирает; слушает 127.0.0.1, наружу (`--host 0.0.0.0`) не
выставляй: авторизации нет. `--port`, `--no-browser` имеются.

Конфиг (`~/.config/feedzine/config.toml`):

```toml
title = "Мой журнал"
out = "~/Books/feedzine"          # куда класть выпуски
preset = "reader"                # reader | eink | mini | tiny | hq
full_text = "auto"               # auto: полный текст для Habr, сводки для остальных
max_per_feed = 10                # статей на фид в выпуске

[[feed]]
name = "Хабр · статьи"
url = "https://habr.com/ru/rss/articles/"

[[feed]]
name = "Хабр · Python"
url = "https://habr.com/ru/rss/hubs/python/"
max = 5
section = "Хабр"                 # своя секция вместо имени фида

[[feed]]
name = "DTF · главное"
url = "https://dtf.ru/rss/all"
full_text = false                # только сводки
exclude_tags = ["реклама"]       # тег-фильтр на фиде
```

- `full_text` глобально (`auto | true | false`) и на фид. `auto` сам
  понимает, когда тянуть полный текст: Habr (kek/v2 `textHtml`) и фиды-
  агрегаторы (Hacker News, rss-bridge, telegram-экспорты), у которых
  сводка — огрызок в пару строк: у таких статьи выгружаются с целевого
  сайта (самый мясный `<article>`/`<main>`, скрипты вырезаются, сниффер
  при необходимости берёт прямую ссылку из описания фида). Обычные блоги
  с внятными сводками сайт не дёргают. `true` — всегда, `false` — никогда.
- `min_article_chars` (глобально и на фиде, default 120) — фильтр пустого
  говна: если после зачистки ссылок, картинок и разметки в теле меньше
  этого объёма прозы, статья не попадает в выпуск — «пачки ссылок» и
  заглушки не собираются. Если всё накопленное отсеялось — выпуск не
  создаётся, накопитель очищается. `0` отключает фильтр (короткие посты
  из telegram-журналов).
- `max` на фид ограничивает выпуск, если фид зашумлён. Сверх капа статьи
  помечаются прочитанными (не переносятся в следующий выпуск).
- тег-фильтры: `include_tags` / `exclude_tags`, глобально и на фиде
  (фид переопределяет глобальные). Теги статьи — это `<category>` RSS
  (включая `dc:subject`) и `category` Atom. Совпадение регистронезависимо;
  `include_tags = []` — фильтра нет. Отфильтрованное помечается прочитанным
  и в следующие выпуски не возвращается (та же семантика, что у капа).
- секции выпуска: `section` у фида или его имя;
  внутренние заголовки статей демо́тятся и не засоряют навигацию
  (заголовки сохраняются — только понижаются уровнем; код в блоках
  ``` не трогается).

Выпуски именуются `Журнал_007_2026-10-04.epub` (номер + дата; расширение —
по формату). `issue` идемпотентен: нового нет — выпуск не собирается,
state не меняется. `keep_issues = N` оставляет последние N выпусков
текущего формата, старые удаляет (0 — хранить все).

## Периодические сводки

`period` в конфиге: `day` (default — каждый запуск = выпуск), `week`, `month`.

Сводки строятся на накопителе: каждый прогон помечает статьи прочитанными
и складывает прошедшее фильтры в очередь (`state.pending`). Когда наступает
граница периода — ISO-неделя (сводка выходит в понедельник при daily-таймере)
или месяц (1-го числа) — всё накопленное собирается одним выпуском.

- `feedzine issue --force` — собрать сводку сейчас, не дожидаясь границы;
- `feedzine issue --dry-run` — сколько накопилось и пора ли собирать;
- провал сборки статьи не теряет — накопитель очищается только после
  успешного выпуска;
- накопленные статьи несут снимок настроек фида на момент сбора: правки
  конфига (переименование, full_text) не ломают уже накопленное.

## Форматы выпуска

`format` в конфиге (или `--format`):

| Формат | Что получается |
|---|---|
| `epub` (default) | EPUB с обложкой и TOC, zip перепакован на level 9 |
| `html` | один самодостаточный файл — картинки и CSS зашиты внутрь (`--embed-resources`) |
| `md` | голый markdown; картинки остаются в `workdir/img/` (пути относительные) |

## Обложки

`cover` в конфиге:

| Режим | Обложка |
|---|---|
| `auto` (default) | первая картинка выпуска; нет картинок — генерируемая |
| `image` | только первая картинка; нет — без обложки |
| `generated` | всегда генерируемая |
| `off` | без обложки |

Генерируемая обложка — монохромный узор во всю ширину (фракталы
Мандельброта/Жюлиа, тайлинг Трюше, филлотаксис, муар, фрактальное дерево,
ридглайн, треугольник Серпинского), поверх — заголовок, номер выпуска на
белой плашке, дата, секции. Узор выбирается детерминированно по номеру
выпуска: пересборка того же выпуска даёт ту же обложку, новый выпуск —
новый узор. `cover_pattern` фиксирует узор: `mandelbrot | julia | truchet
| phyllotaxis | moire | tree | ridge | sierpinski`.

**Размер обложки — от пресета экрана**: маленькие читалки получают
маленькую обложку, вся геометрия масштабируется. Шрифт — DejaVu Serif из
nix-пакета; свой — через env `FEEDZINE_FONT`. Символы, которых нет в
шрифте (эмодзи, CJK), на обложку не попадают — выкидываются с пометкой в
логе, вместо tofu-квадратов. Обложка — только для EPUB; html/md выпуски
идут без неё.

## Несколько журналов

Фиды можно разбивать на отдельные журналы: у каждого свой заголовок,
каталог выпусков (`out/<id>/`), период и нумерация. Хабр — weekly-дайджест,
Telegram-каналы — daily, main — как раньше:

```toml
title = "Главный"

[[feed]]
name = "Хабр · статьи"
url = "https://habr.com/ru/rss/articles/"

[[feed]]
name = "Hacker News"
url = "https://hnrss.org/frontpage"
full_text = true           # сниффер: полные статьи по ссылкам из фида
journal = "hn"             # отдельный журнал

[[feed]]
name = "Telegram · каналы"
url = "https://t.me/s/example_feed/rss"
journal = "tg"

[journal.hn]               # пустые значения наследуют глобальные
title = "HN Дайджест"
period = "week"            # main — daily, HN — раз в неделю

[journal.tg]
title = "Telegram"
keep_issues = 30
```

State общий (один `seen`-пул), но счётчики выпусков, накопители и границы
периодов — у каждого журнала свои; старый flat-state мигрируется сам.
Провал сборки одного журнала не трогает остальные. Фиды без `journal`
попадают в журнал main — он живёт в `out/` под `cfg.title`, как до
разбиения.

## Calibre и доставка на читалку

- `calibre_library = "~/Calibre"` — после сборки EPUB добавляется в библиотеку
  через `calibredb add` (нужен `calibredb` в PATH; нет — предупреждение и дальше).
- `post_issue = "…"` — shell-хук после успешной сборки: `%f` подставляется
  путь к EPUB, плюс env `FEEDZINE_EPUB`. Универсальный шов доставки:

```toml
# syncthing-папка, которую читалка забирает по USB/Wi-Fi:
post_issue = "cp %f ~/Sync/koreader/feedzine/"
# или сразу в calibre-библиотеку без calibredb:
# post_issue = "cp %f ~/Calibre/_feedzine/"
```

KOReader'у отдельной интеграции не нужно: это обычный EPUB — достаточно
попадания файла в видимую ему папку (Syncthing, rsync, USB).

## Пресеты и маленькие экраны

| Пресет | Картинки | Обложка |
|---|---|---|
| `reader` (default) | 480px true grayscale, бокс 480×800, JPEG q85 | 600×800 |
| `eink` | 480px цветной, бокс 480×800 | 600×800 |
| `mini` | 360px ч/б — мелкие e-ink 5–6" | 450×600 |
| `tiny` | 240px ч/б — совсем маленькие экраны | 300×400 |
| `hq` | 900px цветной | 900×1200 |

Кэш картинок в `~/.cache/feedzine/img/<preset>/`, имена — sha1 URL:
повторные выпуски не перекачивают то, что уже лежит. Пресет задаёт и
размер картинок, и размер генерируемой обложки — маленькие читалки
получают пропорционально уменьшенный выпуск.

## Сжатие

- картинки: пресет уже режет размер/глубину/quality; поверх —
  `img_quality = 40..95` в конфиге (0 = качество пресета);
- EPUB после pandoc перепаковывается zip'ом на level 9
  (mimetype по OCF первым и без сжатия — читалки не ломаются);
- `keep_issues = N` не даёт старым выпускам копиться в `out`.

## Home Manager

flake экспортирует модуль `homeManagerModules.feedzine` — установка, конфиг
и таймер декларативно:

```nix
# flake.nix вашего окружения
inputs.feedzine.url = "github:71g3pf4c3/feedzine";
```

```nix
# конфиг home-manager
imports = [ inputs.feedzine.homeManagerModules.feedzine ];

programs.feedzine = {
  enable = true;
  settings = {
    title = "Мой журнал";
    out = "~/Books/feedzine";
    feed = [
      { name = "Хабр · статьи"; url = "https://habr.com/ru/rss/articles/"; }
      { name = "Хабр · Python"; url = "https://habr.com/ru/rss/hubs/python/"; max = 5; section = "Хабр"; }
    ];
  };
  timer = {                     # systemd user timer
    enable = true;              # systemctl --user list-timers feedzine
    onCalendar = "*-*-* 07:00:00";
    persistent = true;          # навёрстывать пропущенное
  };
};
```

- `settings` — это `~/.config/feedzine/config.toml`: список `feed`
  сериализуется в `[[feed]]`, поля те же, что понимает `load_config`.
- Пока конфигом управляет модуль, `feedzine init` не нужен (и вреден —
  перепишет управляемый файл).
- Сервис `feedzine.service` объявляется при любом `enable` — выпуск можно
  дёрнуть вручную: `systemctl --user start feedzine`.

## Регулярный выпуск

Пользователям Home Manager таймер даёт модуль (см. выше); вручную —
systemd user timer (`~/.config/systemd/user/feedzine.timer`):

```ini
[Unit]
Description=feedzine issue

[Timer]
OnCalendar=daily 7:00
Persistent=true

[Install]
WantedBy=timers.target
```

`~/.config/systemd/user/feedzine.service`:

```ini
[Service]
Type=oneshot
ExecStart=%h/.nix-profile/bin/feedzine issue
```

## Как это работает

- фиды: RSS 2.0 и Atom через `xml.etree`, дедуп по `guid`/`id`/`link`;
  сеть — httpx, повторы на транспортные сбои (4xx/5xx не повторяются)
- конфиг валидируется pydantic: опечатка в ключе или кривое значение —
  понятная ошибка, а не молчаливый дефолт
- полный текст Habr: `GET https://habr.com/kek/v2/articles/<id>/` → `textHtml`;
  чужие сайты: первый `<article>…</article>` достаточной длины из SSR-страницы
- HTML → Markdown: pandoc; картинки вырезаются из HTML, качаются, обрабатываются
  (Pillow: grayscale/box/resize, baseline JPEG), ссылки переписываются на локальные
- EPUB: pandoc + книжная типографика (та же eink.css, что у [dtf-dl](../dtf-dl))

## Ограничения

- Habr: полнотекстовый fetcher рассчитан на kek/v2 — если Хабр его прикроет,
  фид продолжит работать в режиме сводок
- `full_text=true` для произвольных сайтов — best effort: нужен внятный
  `<article>`/`<main>` в разметке; JS-only страницы не выгружаются
  (сниффер по ссылкам из описания тоже не спасёт)
- комментарии и закрытые посты не поддерживаются
